# App 播放空响应修复记录

## 问题与依据

部分 App 播放请求返回 HTTP 200、空响应，用户无法取得分集片源。原重试路径在当前 V5 请求失败后传入空 video ID，转用 legacy 端点；该路径不能继续尝试当前 V5 取源。

2026-11-19 前一轮接口排查记录使用《镇妖博物馆》第 1、2 集（分集 ID `7696045152510430232`、`7696045155563883544`），观察到同一分集使用不同匿名设备身份时结果不同，也观察到 legacy 请求空响应。记录支持优先更新匿名播放身份、继续尝试 V5 的恢复策略，不能确定服务端内部拒绝原因。此前汇总中的“50% → 90%”“约 10% 失败”等表述没有完整逐次脱敏回执支撑，本记录不将其作为验收指标，也不推算长期成功率。

## 修复行为

- 空响应后继续使用 V5，交替官方主、备主机，每轮重新生成请求签名。
- 时间预算允许时重新注册匿名播放设备身份；搜索和账号身份逻辑保持原有行为。非明确拒绝的注册失败保留上一身份，不能保证每轮都获得新身份。
- 模型请求最多五次，仅对 `EMPTY_RESPONSE` 重试。403、429、业务拒绝、取消等错误不因该恢复路径循环重试。
- 初次注册单独使用既有注册预算（8 秒）；注册完成后，模型重试与后续 fallback 合计受 20 秒上限约束。每个模型请求最多 12 秒，fallback 共用成功模型请求的截止时间；排队等待另计。
- 保留 URL、分集身份、时长、加密与清晰度校验，以及原有拒绝缓存和调用队列。

## 验证与证据边界

2026-11-19 本轮重新执行 `check-app-source.cjs`（14/14）、`check-app-source-recovery.cjs`、`check-app-source-v5.cjs` 均通过。恢复夹具覆盖空响应后不同设备身份恢复、最多五次模型请求、注册次数上限、HTTP 403/404 不重试，以及取消与截止时间相关场景；测试使用模拟响应，不代表真实服务的可用率。

完整回归、构建、真实下载解码、Windows 安装与最终发行结果统一登记于 [6.17 发行回执](release-6.17.md)，以对应提交和 CI 运行号为准。

本修复未进行实体机 GUI 长时间播放、画中画、连播或看完自动删除验收；公开预览解码也不能替代完整分集播放验收。上游仍可能返回空响应或拒绝，达到边界后向调用方返回错误，由用户决定是否重试。
