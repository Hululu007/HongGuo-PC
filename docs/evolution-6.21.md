# 6.21 自主维护：能力、取舍与验收

2026-11-21。基线为远程 `main` 的 `683cf812`，已公开版本为 6.20（内部 `6.20.0`）。本轮目标是让有大量设置或下载任务的用户更快定位目标，同时隔离设置提交范围、避免批量动作波及隐藏任务。正式发行范围仍为 Windows x64。本页描述源码和验收证据，不是公开发布回执。

## 已落地的改动

- `Settings.jsx`：12 类设置实际筛选，支持宽字符归一化和空格分词；公布匹配数，Enter 跳到首项，Esc 清除（尊重输入法合成），无结果可还原。隐藏时仍保留草稿和保存入口。
- `Settings.jsx`：代理弹窗只提交代理字段；普通保存只提交已编辑字段。写入成功但读取失败时明确说明已保存，不回显未经主进程净化的地址（包括可能嵌入的凭据）；再次打开代理编辑前必须读取最新设置，避免将旧地址写回。迟到的旧读不会覆盖新草稿或已保存的修改。
- `DownloadManager.jsx`：按剧名、任务名、文件名与状态筛选，等待重试与手动处理状态分列。选中项可跨页，筛选外的选中项不参与批量停止、重试或删除；重试失败保留选择，删除仍需确认。
- `check-ui-theme.cjs`：页面和播放器菜单由固定程序表选择，不再将三个被 CodeQL 报警的可变值插入执行字符串。74 次模拟执行验证导航、聚焦、可见性和未知 ID 拒绝。告警状态以远程重新扫描为准。
- `scripts/test.cjs`：并行测试启动前先解析 Electron，避免 Windows 首次解压竞争；`check-streaming.cjs` 为取消检查使用独立响应的 `close` 事件和有界超时，不再以共享标志和 30ms 休眠猜测。
- Windows 候选在测试前核验对应源码归档中的二进制 SHA-256。保留原安装、重装和真实 1.80 升级检查；不因校验顺序变化减少任何门槛。

## 验收边界

- 原生桌面可访问性工具在深色独立客户端输入「代理」并观察到筛选结果，后续因 `surface_replaced` 未能派发点击。随后扩展已有 Electron 验收驱动，执行 `node scripts/check-ui-theme.cjs --settings-search`：深浅两主题均通过实际卡片隐藏、Enter 移焦点、Esc 清除、空结果恢复及代理弹窗初始焦点/Tab/Esc/返回焦点检查。真实截图与记录见 [证据目录](screenshots/settings-search-6.21/evidence.json)。验收驱动以脚本为 Electron 入口，侧栏版本展示 Electron 的 `44.9.1`，不是正式安装包版本；生产包版本仍为 `6.21.0`。没有实际提交代理修改；提交、凭据读回失败、旧读竞争和隐藏草稿由隔离 renderer 回归覆盖。全尺寸全页面视觉矩阵本轮未重跑。
- UI 验收没有播放或下载视频，不触碰正式账号和资料。媒体工具回归日志中的公开预览解码不是完整分集实机播放；本轮不将画中画、连播、观看后自动删除或官方完整分集链路标为已验收。实际运行、安装器升级和应用内更新是三类不同验收。
- 无性能提升百分比。Vite 原有大 chunk 警告仍在；未降低构建阈值，没有引入新依赖。依赖与源码检查、安装器运行和发布状态以实际回执为准。

## 打包产物静态暴露复核

### 1. 总览

以 `electron` 画像只读扫描本机构建 `dist/win-unpacked`，扫描器统计 89 文件、9 个原生二进制；启发式评分 24/D 仅用于排列线索，不是安全评分。本项目本来按 GPL 公开源码，ASAR（未加密的 Electron 归档）可解包不等于秘密泄漏。未执行下载目录脚本，也未改动第三方 DLL 来消除扫描信号。

### 2. 发现清单

| 编号 | 静态线索 | 人工判定与处理 |
|---|---|---|
| PE-SIGN | 安装器与若干二进制缺 Authenticode 签名 | 本机系统查询安装器为 `NotSigned`。实际信任缺口保留，不能将构建器的 signing 日志当作签名成功 |
| WEB-SOURCEMAP | ASAR 内有 57 个依赖 source map | 已用 ASAR 清单核对为 axios、更新器等公开依赖；`dist-react` 无 map。非本轮私密源码泄漏，后续可裁剪冗余文件 |
| PE-PDB | 系统图形 DLL 中有 CodeView/PDB 线索 | 示例 `dxil.dll` 的上游 CI 路径，不是本机账号或项目源码路径；不贸然修改上游签名库 |
| CLR-ASM | `d3dcompiler_47.dll` 命中 `BSJB` 字节 | 仅凭原始字节不能判定自有 .NET 授权逻辑，不作为已确认漏洞 |
| LEAK-INTRANET | ASAR 出现 loopback 模板和开发端口 | 属于本地媒体服务及开发入口；不是私有业务端点。生产 IPC/媒体能力边界另有回归，不建议盲目删去 |
| PE-CFG | 媒体工具等缺 CFG 位 | 属于现有工具链加固机会，不是已证明可利用的内存缺陷；需与工具链更新和解码矩阵一并评估 |

### 3. 证据与修复边界

ASAR 清单核对 `src/native/**/*.test.cjs` 为零，生产 renderer map 为零，依赖 map 为 57。Electron EXE fuse 元数据可读取，但扫描器因文件大小跳过了主 EXE 的完整检查；不能据此写成 fuse/完整性加固完成。官方 npm registry 依赖审计为零告警，仍不等于无逻辑缺陷。正式候选的静态检查与本机源码/包保持区分。

### 4. 客户端无法解决的问题

本应用没有新增付费授权判定或后端，也不把匿名 API 签名算法当作保密凭证。客户端代码和接口必然可读；不能用混淆阻止源码研究。账号会话和代理密码仍须保持操作系统安全存储、脱敏 IPC 与日志边界；更新 SHA-512 解决下载完整性，不等于发布者代码签名信任。没有测量服务端鉴权或风控，不作保证。

### 5. 修复顺序

先保持已覆盖的凭据与文件边界；P1 取得真实 Windows 签名环境后验证证书和更新信任，P2 在独立迭代裁剪依赖 map、评估 fuse 与媒体工具链加固并补生产调试/升级兼容回归。未发现需要本轮撤回已有功能的静态证据，不以全局混淆或删除本地服务替代边界验证。
